# 1. Non-negotiable architecture rules

## 1.1 Tool categories

One source of truth:

```text
HARVEST = Knife + Hoe + Axe
CUTTING = Knife + Axe
```

Implementation authority:

```text
FarmerToolSupport
```

No viewer may duplicate these definitions.

## 1.2 Accepted tool is not required tool

Current hard requirements:

```text
Mature Mushroom Colony -> Knife
Ready Melon             -> Axe
Ready Pumpkin           -> Axe
```

Not hard requirements:

```text
Rice          -> Knife optional
Normal crops  -> Hoe optional
Tomato        -> Hoe optional
Sugar Cane    -> no tool
```

## 1.3 Tool routing into loot

Must remain crop-specific:

```text
Normal crop / Tomato -> Hoe only
Rice                 -> Knife only
Mushroom Colony      -> Knife mandatory
Melon / Pumpkin      -> Axe only
Sugar Cane           -> no TOOL semantics
```

No Fortune leakage from unrelated equipped tools.

## 1.4 No viewer RNG

Jade/JEI/EMI must never:

- roll Cutting outputs;
- advance random state;
- consume inputs;
- damage tools;
- mutate inventories;
- advance machine progress.

## 1.5 JEI and EMI share data

Required model:

```text
shared viewer-neutral data
        |
        +-- JEI renderer/adapter
        +-- EMI renderer/adapter
```

No parallel handwritten guide definitions.

## 1.6 Noise Switch remains local-client

Never store `villagersMuted` in:

- BlockState;
- BlockEntity NBT;
- server SavedData;
- server player data;
- world data.

## 1.7 Noise Switch remains fake redstone only

Visual-only:

- lever;
- powered/unpowered dust.

Never:

- signal;
- comparator;
- neighbor update;
- observer-visible state;
- remote redstone exploit.

## 1.8 Transaction safety

If outputs cannot fit:

```text
no consume
no crop removal
no tool damage
```

## 1.9 Old-world migration

Read order:

```text
EfdcHarvestTool
-> EfdcKnife
-> EruruuKnife
```

Save only modern key.

## 1.10 Supported locales

All textual additions must exist in:

```text
en_us
en_gb
en_au
en_ca
en_nz
es_cl
es_ar
es_es
es_mx
```

## Latest mature-harvest cadence correction — 🟢 IMPLEMENTED / NEEDS CONFIRMATION

A regression was identified where fully mature crops could remain visibly ready for roughly another `farmSpeed` interval before harvesting (for example, a mature Mushroom Colony waiting around 10 seconds at the default `farmSpeed = 10`).

Cause:

```text
growth reaches max age
-> harvest still waits for another 1 / farmSpeed success
```

Corrected model:

```text
growth phase
-> controlled by farmSpeed RNG

final mature stage
-> deterministic harvest attempt on each one-second Farmer cadence
-> no second farmSpeed RNG gate
```

Covered by the correction:

- normal age-based crops;
- mature Farmer's Delight Mushroom Colonies;
- mature Tomato base section;
- mature Tomato Rope 1;
- mature Tomato Rope 2.

Already-correct special cases remain unchanged:

- Rice mature panicles already harvest on the next one-second cadence;
- Sugar Cane height 3 already harvests on the next one-second cadence;
- ready Melon/Pumpkin fruit already retries harvest on the next one-second cadence.

Blocked mature crops remain in standby:

- missing/wrong required tool;
- invalid/missing adult Farmer villager;
- insufficient output capacity.

No crop is reset and no item/tool is consumed while blocked.

Validation still required:

- [ ] mature Mushroom + Knife harvest latency <= next one-second cadence;
- [ ] waiting Mushroom resumes <= next cadence after inserting Knife;
- [ ] mature normal crop latency <= next cadence;
- [ ] mature Tomato base/rope latency <= next cadence;
- [ ] output-full mature crops remain intact.
